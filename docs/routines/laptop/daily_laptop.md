# Routine on the office laptop: daily collection (TrendX, CPI, catalogue) → Scraping Projects panel

Runs as ONE scheduled task of the Claude desktop app on the Windows laptop (Claude Code, local), once a day, three parts one after
the other. Same work as the three cloud routines (`cpi_daily_scrape.md`, `catalogue_daily_crawl.md`, TrendX in `README.md`), with
the differences the laptop needs: Windows commands, one office connection (so Carrefour and Lulu are never asked by two
processes at once, at least 2.5 s between requests per shop), and the scripts' stop-after-5-refusals rule. The code that runs is
the panel's `system_bundle`, never the git branch.

Prompt:

````text
Daily job on the office laptop (Windows, Claude Code, folder Desktop/cpi). Three parts in this order, one after the other: A) TrendX commodity prices, B) the CPI basket (Carrefour and Lulu, Dubai; 1,301 lines), C) the product catalogue of six stores. Results go into the user's "Scraping Projects" panel artifact: https://claude.ai/artifact/FSURninVx3TmNCeFYDyxUn . Work unattended; do not ask questions. If a part fails, say so and go on to the next one. Rules that never bend: never type, invent or carry forward a price; no VPN, proxy, changed browser identity or any other way around a block; a page the shop refuses stays unread and is reported as refused/blocked, never as "not found" or "0 products"; the scripts keep at least 2.5 s between requests to a shop and stop asking a shop after 5 refused pages in a row, do not change that; never start two processes that ask the same shop at the same time. Use `python` (not python3), and forward slashes in every path. Run shell commands from the folder named in each step. Environment variables: in Git Bash prefix the command (`CPI_PINS=... python ...`); in PowerShell set `$env:CPI_PINS='...'` first.

0. Setup (once per run).
   - B = the folder Desktop/cpi under the user's profile (USERPROFILE). H = B/repo (a git clone holding only the helper scripts). Dubai date today = D. Make S = B/work/D and create S/w, S/te.
   - If H does not exist: `git clone --branch claude/sleepy-lamport-dwu4iw https://github.com/waleedhuniti/CPI-Web-Scarping.git H`. Otherwise in H: `git pull origin claude/sleepy-lamport-dwu4iw`. (H is used only for scripts/pc/rebuild_code.py; the code that runs comes from the panel below.)
   - `python -m pip install -q "scrapling[fetchers]" openpyxl pillow pillow-heif beautifulsoup4`.
   - Load ArtifactData (ToolSearch "select:ArtifactData") and make sure the Artifact tool works. If either is missing, stop and report that (the scraping needs them to read the code and store the results).
   - With the panel url, read with out_dir S/w:
     action "list", collection "system_bundle", query {"limit": 50};
     action "list", collection "projects/cpi/basket", query {"limit": 100};
     action "get", collection "projects/cpi/pins", doc_id "current" (remember its version);
     action "get", collection "projects/cpi/products", doc_id "latest" (remember its version; fields history_asset, panel_asset, days);
     action "get", collection "projects/cpi/catalogue", doc_id "latest" (remember its version; fields rows_asset, thumbs_assets, history_asset, date).
   - From H: `python scripts/pc/rebuild_code.py S`. It writes the code to S/repo (call it R), the basket to R/data/basket/basket.json and the pins to S/pins.json, and raises the crawl pacing to 2.5 s. If it prints an error, stop and report it.
   - If the products doc has a history_asset id, download it with the Artifact tool (action "read", panel url, path = the id) and call the local file PREV, else PREV is "-". If the catalogue doc has a rows_asset id, download it the same way: CAT (a catalogue.json file); if none, CAT stays empty.
   - STARTED = the current UTC time in ISO 8601 (e.g. 2026-11-09T05:00:05+00:00).

PART A, TrendX (about 3 minutes). Work in S/te.
   A1. ArtifactData "get" (panel url, collection "system", doc_id "te_daily", out_dir S/te/sys). Write the scripts out: `python -c "import json;d=json.load(open('sys/system/te_daily.json'));d=d.get('data',d);[open(n+'.py','w').write(d[n]) for n in ('collect_te','build_xlsx','to_panel')]"`.
   A2. `python collect_te.py` (prints the JSON file, e.g. te_2026-11-09.json 107 rows). If it fails (HTTP error, block or "ERROR: only N rows parsed"): if the Apify connector tool apify--web-fetch is available use it on https://tradingeconomics.com/commodities (formats ["html"]) and read the dataset with get-dataset-items (fields "html", limit 1), save items[0].html to page.html, run `python collect_te.py page.html`; if it is not available or fails too, stop Part A and report the error. Never type prices.
   A3. Commodity Price Log (https://claude.ai/artifact/XuUGyJcKQEZntxSELCaELE): the document id is the run_date from the JSON. ArtifactData "get" (collection "days", doc_id <run_date>). If missing, "set" collection "days", doc_id <run_date>, file_path <the JSON file>; if it exists, the same "set" plus if_version. Check with "get".
   A4. Panel: ArtifactData "list" (panel url, collection "projects/te/basket", query {"limit": 100}, out_dir S/te/panel). `python to_panel.py <the JSON file>` prints `RUN_ID <id> ...` and writes out/run.json, out/c000.json, out/last.json. Then one "batch" on the panel url: op "set" collection "projects/te/runs" doc_id <RUN_ID> file_path S/te/out/run.json, and op "set" collection "projects/te/runs/<RUN_ID>/rows" doc_id "c000" file_path S/te/out/c000.json. Then "get" collection "projects" doc_id "te" for its version and "update" it with file_path S/te/out/last.json and if_version. If this fails, go on and mention it.
   A5. Excel: ArtifactData "list" (url of the Commodity Price Log, collection "days", query {"limit": 1000}, out_dir S/te/all; follow next_cursor into the same out_dir). Before running build_xlsx.py, replace the output folder in it: `python -c "t=open('build_xlsx.py').read().replace('/mnt/user-data/outputs','B/out');open('build_xlsx.py','w').write(t)"` (use the real B with forward slashes), then `python build_xlsx.py`. It writes B/out/Commodity_Price_Log.xlsx. If SendUserFile is available call it with that path (status "proactive"). If this step fails, mention it.

PART B, CPI basket (about 75-100 minutes). Work in R.
   B1. Start these two in the background (Bash run_in_background, timeout 3 hours each); they ask different shops, so they may run together: `python -I scripts/scrapling_search.py carrefour data/runs/D_daily --delay 2.5 --stop-after 5` and `python -I scripts/scrapling_search.py lulu data/runs/D_daily --delay 2.5 --stop-after 5`. Wait for both to finish (their background task notifications). Afterwards read data/runs/D_daily/carrefour_status.json and lulu_status.json: state "blocked" means the shop refused us; remember it for the final report (do not retry, do not look for another way in).
   B2. Then, alone, with the environment variable CPI_PINS=S/pins.json set: `python -I scripts/scrapling_category.py data/runs/D_daily --delay 2.5` (about 35-45 minutes; it reads Carrefour through its search pages and Lulu through its category pages, and writes crawl_status.json).
   B3. In this order (CPI_PINS=S/pins.json set for the first command):
       `python -I scripts/combine_run.py data/runs/D_daily`
       `python -I scripts/name_live.py data/runs/D_daily` (if it fails, go on without it)
       `python -I scripts/product_panel.py update PREV data/runs/D_daily/catalog.csv D data/runs/D_daily/history.json` (PREV or -)
       `python -I scripts/product_panel.py series data/runs/D_daily/history.json data/runs/D_daily`
       `CPI_CATALOGUE_JSON=CAT python -I scripts/panel_run.py data/runs/D_daily STARTED` (first pass; leave the variable out when CAT is empty)
       `python -I scripts/fetch_thumbs.py data/runs/D_daily --found-only`
       `CPI_CATALOGUE_JSON=CAT python -I scripts/panel_run.py data/runs/D_daily STARTED` (second pass; it prints `RUN_ID <id> chunks <n> ...` and writes data/runs/D_daily/panel/run.json, cNNN.json, tNNN.json, last.json)
   B4. Store the run in the panel with ArtifactData "batch" calls (at most 50 writes and about 900 KB of files per call; split into several calls; run.json in the last one): op "set", collection "projects/cpi/runs/<RUN_ID>/rows", doc_id "cNNN", file_path each panel/cNNN.json; op "set", collection "projects/cpi/runs/<RUN_ID>/thumbs", doc_id "tNNN", file_path each panel/tNNN.json; op "set", collection "projects/cpi/runs", doc_id <RUN_ID>, file_path R/data/runs/D_daily/panel/run.json. Then "get" collection "projects" doc_id "cpi" for its version and "update" it with file_path R/data/runs/D_daily/panel/last.json and if_version.
   B5. Save the pins and the product history (never delete them): (a) `python -c "import json;p=json.load(open('S/pins.json'));json.dump({'pins':p},open('S/pins_doc.json','w'),ensure_ascii=False)"` then ArtifactData "set" collection "projects/cpi/pins" doc_id "current" file_path S/pins_doc.json if_version = the version read in step 0 (re-read if changed). (b) Upload R/data/runs/D_daily/history.json and product_panel.csv as assets with the Artifact tool, ONE call per file (action publish, panel url, asset true, file_path); then "set" collection "projects/cpi/products" doc_id "latest" with data {history_asset: <new id>, panel_asset: <new id>, days: <days in history.json>, products: <number of products>} and if_version = the version read in step 0; afterwards delete the OLD history_asset and panel_asset (the ids read in step 0) with the Artifact tool action delete, path = the asset id. Delete nothing else.

PART C, catalogue of six stores (about 40-60 minutes). Work in R.
   C1. Test the stealth browser that Centrepoint and Max need (the existing solve_cloudflare call site, nothing added): `python -I -c "from scrapling.fetchers import StealthyFetcher; p=StealthyFetcher.fetch('https://www.maxfashion.com/ae/en', headless=True, solve_cloudflare=True, timeout=90000); print(p.status, len(p.html_content))"`. If it cannot launch a browser, run `scrapling install` and test again. If it still fails, skip centrepoint and max and say so.
   C2. Start one process per store, in the background together (different shops; timeout 3 hours each), into data/catalogue/D: `python -I scripts/catalogue_crawl.py data/catalogue/D --stores=carrefour --part-only`, and the same for lulu, sharafdg, zara, centrepoint, max. Wait for all by their notifications. If centrepoint or max ends with 0 rows, fix the browser (C1) and run that store once more. A store that hangs more than 2 hours: stop only that process and use what its part_<store>.csv holds. A store that is refused (no rows, refusals in the log) stays empty and is reported; do not retry it more than once.
   C3. In order: `python -I scripts/catalogue_crawl.py data/catalogue/D --merge`; `python -I scripts/fetch_thumbs.py data/catalogue/D`; `python -I scripts/fill_photos.py data/catalogue/D`; `python -I scripts/catalogue_assets.py data/catalogue/D` (writes catalogue.json, thumbs_<group>.json and latest.json).
   C4. Price history (never delete it): from step 0, the catalogue doc's version and fields rows_asset, thumbs_assets, history_asset. Run `python -I scripts/catalogue_history.py update data/catalogue/D <PREVC or -> data/catalogue/D/history.json`. It prints the day number, the entries added and any store skipped because its crawl was incomplete.
   C5. Upload with the Artifact tool, ONE call per file (action publish, panel url, asset true, file_path): catalogue.json, thumbs_food.json, thumbs_household.json, thumbs_personal.json, thumbs_electronics.json, thumbs_clothing.json, thumbs_other.json, history.json. Put the ids into data/catalogue/D/latest.json: rows_asset = the catalogue.json id, thumbs_assets = {food, household, personal, electronics, clothing, other: id}, history_asset = the history.json id. Then "set" collection "projects/cpi/catalogue" doc_id "latest" with file_path data/catalogue/D/latest.json and if_version = the version from step 0 (re-read if changed). Afterwards delete the OLD assets of that previous doc (old rows_asset, old thumbs_assets, old history_asset) with the Artifact tool action delete, path = the asset id. Delete nothing else.

Finish with three lines. A: run_date, rows, the Aluminum Alloy and Aluminum (LME) prices, the panel RUN_ID, days in the Excel. B: RUN_ID, status, accepted/lines for each shop for barcode and category, the state (ok/partial/blocked) of each shop from the status files, how many no-barcode lines have a product-set price, how many lines were filled from the catalogue, how many from the live name search, the number of products in the history. C: date, rows per store, photo coverage, history day number and entries added, and anything that failed or was refused.
````
