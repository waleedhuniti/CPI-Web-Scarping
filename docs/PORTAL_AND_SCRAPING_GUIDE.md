## 2. البورتال (Scraping Projects) — كل التفاصيل

### 2.1 ما هو تقنياً
- ملف HTML واحد (`panel_artifact/scraping-panel.html`) منشور كـ Artifact على claude.ai، **خاص بحسابك**.
- يعمل فقط داخل claude.ai (يحتاج الـ runtime: `db`, `downloads`, `assets`, `mcp`).
- الإصدارات: كل تعديل يُنشر بنفس الرابط (الإصدار الحالي 17).
- الصفحة ثنائية اللغة تقريباً: الواجهة بالعربية (RTL)، الأعمدة والتصدير بالإنجليزية.

### 2.2 المشاريع

### 2.3 التبويبات داخل مشروع CPI
1. **نظرة عامة** — إحصاءات آخر تشغيل، أشرطة النتائج حسب المصدر (باركود / مسح أقسام)، **لوحة الكتالوج اليومي**، **لوحة تطور الأسعار (رسم)**، **لوحة Dataiku (CSV خام)**، وجدول الأسعار القابل للبحث.
2. **تشغيل** — زر «▶ ابدأ السكراب» (للتشغيل اليدوي عبر Claude Code Remote)، وحالة الجدولة اليومية (موعد، تشغيل الآن `fire_trigger`).
3. **السلة** — عرض/بحث/تعديل/إضافة/حذف أسطر السلة، تصدير CSV، استيراد CSV بأعمدة المشروع، حفظ إلى القاعدة.
4. **الـ Actors** — إعدادات Apify القديمة (متروكة؛ لم تعد تُستخدم في التشغيل اليومي).
5. **النتائج** — قائمة التشغيلات المحفوظة، عرض كل تشغيل بنفس تنسيق Excel الخاص بكم (أزرق/أبيض)، حذف تشغيل، «تنزيل كل الأسعار (Excel)».
6. **إعدادات المشروع** — الاسم، الوصف، موعد التشغيل اليومي، حذف المشروع.

### 2.4 لوحة الكتالوج اليومي (في نظرة عامة)
- تعرض آخر كتالوج: العدد (14,017 منتجاً بتاريخ 12/10 مع الصور).
- أزرار تنزيل **حسب المجموعة**: الكل، غذاء، منزلية/تنظيف، عناية شخصية، إلكترونيات/هواتف/إكسسوارات، ملابس وأحذية، نقل/ترفيه/تعليم.
- جدول للتصفح: صورة، اسم، متجر، سعر، حجم، قسم، رابط. فلتر (بحث، مجموعة، متجر)، **تحديد (✓)** ثم «تنزيل المحدد».
- الملف المنزَّل Excel بتنسيقكم (الرأس كحلي، صفوف بيضاء، عمود Select بقيمة Yes/No، صور مضمَّنة 60px).
- يعرض أول 300 صف فقط في الجدول (للأداء)؛ التنزيل الكامل يضم الكل.

### 2.5 لوحة تطور الأسعار (رسم خطي حي)
- Chart.js من cdnjs. 11 مجموعة بأسمائكم الرسمية:
  - **9 مجموعات غذاء** (0111–0119) من تشغيلات السلة؛
  - **مجموعتان غير غذائيتان** من تاريخ الكتالوج: «السلع المنزلية غير المعمرة» و«أجهزة أخرى (غير كهربائية) وأصناف ومنتجات معدة للعناية الشخصية» (التخصيص بالأقسام بقاعدة مكتوبة في `CH_NONFOOD` داخل الصفحة — تخمين مني يجب أن تراجعوه).
- مقياسان: **الرقم القياسي** (الافتراضي: متوسط هندسي لتغيّر سعر نفس المنتج في نفس المتجر بين يومين متتاليين، متسلسل، أول يوم = 100، أوزان متساوية) أو **متوسط السعر**.
- فلتر المتجر (كارفور/لولو/الكل). نقر الاسم في المفتاح يخفي/يُظهر الخط.
- ⚠ يحتاج يومين على الأقل؛ والمجموعتان غير الغذائيتين تحتاجان ملف التاريخ (قسم 7).

### 2.6 لوحة Dataiku (CSV خام)
أزرار تنزيل ملفات نصية بسيطة (UTF-8، بدون BOM، بلا صور أو تنسيق):
| الزر | المحتوى |
|---|---|
| كل الأسعار والتشغيلات (CSV) | كل التشغيلات المحفوظة، كل الأسطر (موجود/غير موجود)، كل الحقول، + أعمدة السلة (class/group/qty/barcode/origin) |
| الكتالوج الكامل (CSV) | كل منتجات آخر كتالوج بكل الأعمدة (CPI فقط) |
| سجل الأسعار اليومي (CSV) | **سجل التغيرات** (تاريخ، متجر، رقم المنتج، عنوان، سعر، سعر قبل الخصم، مجموعة، قسم، رابط) — يظهر بعد أول تشغيل يخزّن التاريخ |

### 2.7 قاعدة بيانات البورتال (Artifact DB)
حدود: وثيقة ≤ 256 KiB، ≤ 25,000 وثيقة. لذلك تُقسَّم الصفوف إلى أجزاء (~50 KB لكل جزء).

| المسار | المحتوى |
|---|---|
| `projects/<id>` | تعريف المشروع (الاسم، النوع، الأعمدة، الجدولة `schedule.trigger_id`، `lastRun`...) |
| `projects/<id>/basket/<n>` | أسطر السلة (`items`: item_code، الاسم العربي، الماركة، الباركود، الكمية، المنشأ، المجموعة) |
| `projects/<id>/runs/<runId>` | ملخص التشغيل: `startedAt`, `finishedAt`, `status`, `count`, `accepted`, `chunks`, `summary` لكل متجر/مصدر، `log` |
| `projects/<id>/runs/<runId>/rows/cNNN` | صفوف التشغيل (كل سطر: متجر × صنف: السعر، الحالة، العنوان، الرابط، الصورة، `accepted yes/no`...) |
| `projects/<id>/runs/<runId>/thumbs/tNNN` | صور مصغرة للتشغيل (base64 JPEG) |
| `projects/cpi/catalogue/latest` | مؤشّر الكتالوج: التاريخ، العدد، المجموعات، المتاجر، **معرّفات الملفات** (`rows_asset`, `thumbs_assets`, `history_asset`) |
| `system_bundle/b0,b1,b2` | **كود الروتينات** (ملفات Python + config) تقرؤه الروتينات وتعيد بناءه |
| `system/te_daily`, `system/cpi_daily` | سكربتات TrendX وCPI القديمة |

### 2.8 ملفات Assets (حد 20 MiB لكل ملف، رفع كل JSON في استدعاء منفصل)
- `catalogue.json` (≈7 MB) — كل الصفوف.
- `thumbs_<group>.json` ×6 — صور 56px (JPEG جودة 55) لكل مجموعة تنزيل.
- `history.json` — تاريخ الأسعار (قسم 7).
- الصفحة تقرأها عبر `/_blob/<id>`.

### 2.9 التشغيل داخل البورتال
- زر التشغيل يستدعي أدوات Claude Code Remote (`fire_trigger`, `update_trigger`, `get_trigger`) — يشغّل نفس الروتين السحابي، لا يسحب من المتصفح.
- حماية: كل قراءة تتم وثيقة بوثيقة، والبيانات المجمّدة تُنسخ (`plain()`) قبل التعديل (حلّ خطأ read-only property).

## 3. كيف نعمل Web Scraping — الأساس

### 3.1 المكتبة: Scrapling (بدون Apify)
- **`FetcherSession(impersonate="chrome")`** — طلبات HTTP عادية لكن ببصمة TLS لمتصفح Chrome. تكفي لـ Carrefour وLulu وZara وAlgolia (Sharaf DG). سريعة، بدون متصفح.
- **`StealthyFetcher.fetch(headless=True, solve_cloudflare=True)`** — متصفح خفي حقيقي لتجاوز حماية Cloudflare. يُستخدم لـ Sharaf DG (صور)، Centrepoint، Max.
- **`Selector`** لاستخراج العناصر من HTML.
- مبادئ: طلب واحد في كل مرة لكل متجر، تأخير `--delay` (+ عشوائي 0–1 ث)، 3 محاولات للصفحة، لا اختراع أسعار أبداً.

### 3.2 كل متجر: من أين ومن كيف
| المتجر | المصدر | ملاحظات |
|---|---|---|
| **Carrefour** | صفحات البحث/الأقسام (بطاقات المنتجات تُرسَم على الخادم) | سعر الفواكه/اللحوم المتغيرة الوزن **لوحدة وزن (مثلاً 500 غ)** وليس للكيلو؛ سعر الكيلو في `unit_price`. صور AVIF تُحوَّل بـ `pillow-heif` |

## 5. المطابقة مع السلة (كيف نقرر «موجود / غير موجود»)

السلة: **637 صنفاً** — **384 بباركود**، **253 بلا باركود** (لحوم، أسماك، فواكه، خضار، مخبوزات...). القرار النهائي دائماً **نعم/لا**: وُجد السعر أو لم يوجد (`cpi/decision.py`).

### 5.1 الأصناف بباركود (`scrapling_search.py` + `match_run.py`)
1. يبحث عن الباركود في الموقع (14 خانة GTIN، يعيد الصفر الأول الذي حذفه Excel — `cpi/gtin.py`).
2. **يُقبل فقط** إذا أعاد البحث منتجاً واحداً وكان حجم العبوة = حجم السلة (تسامح 0.5% للتقريب) — `cpi/quantity.py` يقرأ «1 كغ»، «280غ»، «4*1لتر»، «30gx18» ... إلى g/ml/pc.
3. حالات: `barcode_search_match` ✓، `qty_mismatch` ✗ (حجم آخر)، `qty_unit_differs` ✗، `qty_title_url_conflict` ✗ (عنوان يخالف الرابط)...
4. **ملاذ أخير بالاسم** (`name_fallback.py`): لأن منتجات كثيرة لها عدة باركودات ولا يعرض المتجر إلا واحداً. شروط: كل كلمات الماركة في العنوان، 2/3 من كلمات `must_have`، لا `must_not`، **نفس الحجم تماماً**. النتيجة `name_match`.

### 5.2 الأصناف بلا باركود (`scrapling_category.py`)
1. يزحف **الأقسام كاملة** (Carrefour `currentPage=0,1…`، Lulu `page=1,2…`) من `config/categories.json` حتى تختفي المنتجات الجديدة.
2. يطابق كل سطر بمواصفاته الإنجليزية (`specs_en.json`: `must_have`/`must_not`):
   - **أقسام الطازج فقط** للأسطر الطازجة؛ أقسام المجمّد مستثناة إلا إن كان السطر مجمّداً (أُضيفت لأن المخلل ظهر كمانجو طازج).
   - لا عضوي/متبّل/مجمّد ما لم تذكره السلة.
   - السعر يتحول لوحدة السلة: للكيلو، للقطعة، للحزمة (`price_basis` = kg/l/pc/bunch).
   - **المنشأ**: منتج من منشأ السلة = `match`؛ عدة قوائم بفارق >15% = `review_multiple` (الوسيط)؛ المنشأ غير مذكور = `review_origin` (يُقبل إن لم يكن للمنتج إلا سطر واحد)؛ منشأ آخر = `substitute_origin` (غير مقبول الآن — يحتاج سعر الشهر الماضي لقاعدة ±30%)؛ لا شيء = `no_match`.
3. القواعد الكاملة المكتوبة: `docs/name_matching_rules.md`.

### 5.2b تثبيت المنتج المرجعي (Pinning) — منذ 13/10
- **المشكلة:** المطابق كان يختار كل يوم «الوسيط» من القوائم المرشّحة، فيتغير المنتج المختار عندما تتغير القوائم (مثال: سلمون لولو 4.5 كغ ← 2.5 كغ، فبدا السعر كأنه هبط 49%).
- **الحل:** أول منتج مقبول لكل سطر × متجر **يُثبَّت** (`url` + عنوان + تاريخ). في الأيام التالية يُسعَّر **نفس الرابط** حتى لو ظهرت قوائم أرخص. الكود: `scripts/scrapling_category.py` (متغير البيئة `CPI_PINS`).
- **اختفاء المنتج المثبَّت:** السطر «غير موجود» ذلك اليوم (`pinned_missing`)، وبعد **3 أيام متتالية** يُختار منتج جديد ويُثبَّت (`repinned`) — ويجب أن يربط الفريق السعر القديم بالجديد.
- **التخزين:** وثيقة `projects/cpi/pins/current` في البورتال (112 تثبيتاً بُذرت من تشغيل 13/10)؛ الروتين يقرؤها قبل التشغيل ويحفظها بعده.
- يُثبَّت فقط ما كان مقبولاً (`match` أو `review_multiple`)؛ الباركود لا يحتاج تثبيتاً لأن الباركود نفسه يحدد المنتج.
- الرسم: الرقم القياسي لا يقارن إلا نفس المنتج (نفس العنوان)، ومتوسط السعر = متوسط أول يوم × الرقم القياسي.

## 7. تاريخ الأسعار وتحليل السوق

### 7.1 ماذا يُحفظ
`history.json` يخزّن **التغيرات فقط**: لكل منتج `[يوم، سعر، سعر عادي]` عند تغيّر السعر، و`[يوم, null, null]` عند اختفائه. حجم البداية ≈3.7 MB لـ 14 ألف منتج، وينمو قليلاً كل يوم.

- متجر رجع بأقل من نصف منتجاته المعتادة (زحف فاشل) **لا** يُسجَّل كاختفاء.
- إعادة التشغيل في نفس اليوم تستبدل ذلك اليوم.
- المفتاح: `outlet|retailer_id` (أو الرابط).

### 7.2 اكتشاف العروض (الخطة)
بدل الاعتماد على «السعر قبل الخصم» (Lulu لا يعرضه): عروض = **انخفاض كبير مؤقت يعود** (التغير العادي 1–3 درهم)، يُكتشف بمرشّح عروض على السلسلة بعد 1–3 أشهر. حدود: عرض يبدأ وينتهي بين زحفين يومين لا يُرى؛ انخفاض لا يعود لا يُميَّز عن تخفيض دائم قبل أسابيع.

### 7.3 ما لا يمكن عمله
المتاجر لا تنشر تاريخ أسعارها؛ **كل يوم يفوت لا يُسترد**.

## 9. Dataiku وحساب الرقم القياسي

### 9.1 سلسلتكم الحالية
`Step3_prices_clean` → **Step5** (متوسط `avg_price` لكل شهر/صنف: حسابي أو هندسي، يستبعد `outlier_check`) → **Step6** (`price_relative = avg_price / base_avg_price × 100` مع الأوزان) → **Step7** (`index = Σ(w × relative) / Σ(w) × 100` لكل مستوى: قسم، مجموعة، فئة، فئة فرعية، الكل).

### 9.2 كيف تدخل بياناتنا
نقطة الدخول عند Step3: صف لكل منتج/متجر/شهر (وليس لكل يوم، وإلا صار `n_sources` = أيام). ملاحظات:
- **مجموعة المنتجات الثابتة**: `base_avg_price` ومتوسط كل شهر يجب أن يستخدما نفس المنتجات، وإلا تتحرك النسبة بسبب التركيبة.
- الأوزان من مسح إنفاق الأسر، وليست من البورتال.
- التغطية 504 من 1,274 سطراً: Step7 يعيد توزيع الأوزان على الموجود فقط.
- وصفات Dataiku الجاهزة: `dataiku/recipe_cpi_scrape.py`, `recipe_catalogue.py`, `recipe_github_feed.py` (وشرحها `docs/dataiku.md`). قرارنا الحالي: **التنزيل من البورتال**؛ التكامل المباشر مؤجَّل بطلبكم.

## 12. حدود النظام وما يجب الانتباه إليه (بصدق)

1. **تغطية السلة نحو 40%** (504 من 1,274)؛ أصناف الأقسام (253) تغطيتها منخفضة (~20%).
2. **أسطر الأقسام**: كان المنتج المطابَق يتغير بين يومين؛ عولج بالتثبيت (قسم 5.2b) من تشغيل 14/10 فصاعداً، ولم يُختبر بعد على تشغيل سحابي حقيقي.
3. **Lulu**: لا سعر قبل الخصم؛ عنوان التوصيل لم تُتحقق آثاره على السعر.
4. **Centrepoint/Max** قد يرجعان صفراً في الروتين السحابي (تعديل غير مُختبَر).
5. **مدة الزحف**: الكتالوج ساعة أو أكثر (Carrefour/Lulu الأبطأ).
6. **لا Spinneys ولا Nesto.**
7. **الأوزان**: لا يوجد وزن للمتاجر ولا لمجموعات المنتجات داخل البورتال؛ الرسم بأوزان متساوية. حصة السوق: أقرب رقم USDA يقول Carrefour ≈27% وLulu ≈24% من الإمارات (غير مؤكد السنة/النطاق).
8. **الروتين لا يدفع إلى GitHub** والبورتال يحتفظ بآخر كتالوج + تاريخ مضغوط؛ باقي الكتالوجات القديمة لا تُحفظ.
9. **حدود Artifact**: وثيقة 256 KiB، ملف 20 MiB، 25,000 وثيقة.
10. **تشغيل 12/10 06:00** هو تشغيل يدوي مني بقواعد مطابقة محسّنة؛ تشغيل 13/10 04:03 هو أول تشغيل مجدول بالقواعد الجديدة.

## 15. مسرد

- **COICOP**: تصنيف الاستهلاك الفردي حسب الغرض (011 = الغذاء). `group_code` = 0111–0119.
- **GTIN/EAN/UPC**: أرقام الباركود؛ القانوني 14 خانة.
- **Scrapling**: مكتبة Python للسحب بدل Apify.
- **Routine**: مهمة مجدولة على claude.ai.
- **Artifact**: صفحة HTML مستضافة على claude.ai مع قاعدة بيانات وملفات.
- **Jevons**: متوسط هندسي لنسب الأسعار؛ الشائع في الأرقام القياسية الأولية.
- **`found / not_found`**: القرار النهائي لكل سطر × متجر.
- **price_basis**: وحدة السعر المحوَّل (`kg`, `l`, `pc`, `bunch`).
